# CTM9 — Финальная проверка и чек-лист приёмки

Промт без правок кода: агент прогоняет сценарии и отмечает результат. Если что-то не проходит —
возвращается к соответствующему промту (указан в скобках), НЕ переписывая логику «на глаз».

## 0. Сборка и регрессия

- [ ] `dotnet build` — без ошибок и предупреждений по затронутым файлам.
- [ ] Существующие тесты дерева зелёные (фильтр, ленивая загрузка, состояние).
- [ ] Дерево БЕЗ включённых функций изменения (`Enable* = false`, `CustomMenuItems` пуст) работает
      как прежде: нет контекстного меню, нет DnD, `IClayTreeMutations` не требуется. (CTM3)

## 1. Липкая панель фильтра (CTM4)

- [ ] При ограниченной высоте дерева (`Options.Style="height:400px"`) и длинном списке: панель
      фильтра неподвижна, прокручиваются только узлы.
- [ ] Скролл начинается сразу под фильтром; фон панели непрозрачный.
- [ ] Без ограничения высоты — прежнее поведение (внутреннего скролла нет).

## 2. Tooltip и выделение (CTM5)

- [ ] Длинное имя обрезается многоточием; при наведении — нативный tooltip с полным именем.
- [ ] Короткое имя tooltip не показывает.
- [ ] Клик по узлу выделяет его контрастным стилем приложения; предыдущее выделение снимается.
- [ ] Выделение не влияет на разворачивание/сворачивание; подсвечивается только строка узла.
- [ ] Событие `OnNodeClick` по-прежнему вызывается при выделении.

## 3. Контекстное меню — редактирование (CTM7)

- [ ] Пункт «Редактировать» виден только при `EnableEdit = true`.
- [ ] Диалог показывает текущее название и путь к НОДЕ (функция + направление из опций).
- [ ] «ОК» → `UpdateNodeAsync(nodeId, EditColumn, value)`; текст ноды перечитан из БД; уровень НЕ
      перезагружался; выделение и раскрытость не изменились.
- [ ] «Обновить» перечитывает значение и путь из БД, не закрывая диалог.
- [ ] «Отмена» ничего не меняет.
- [ ] При `EditColumn = null` и включённом редактировании — понятное исключение.

## 4. Контекстное меню — добавление (CTM7)

- [ ] Пункт «Добавить дочерний» виден только при `EnableAddChild = true`.
- [ ] Диалог: пустое поле, путь к РОДИТЕЛЮ.
- [ ] «ОК» → `AddChildAsync(parentId, EditColumn, value)`; уровень родителя перезагружен; родитель
      раскрыт.
- [ ] Если новая нода не проходит фильтр / не попала в подгруженную порцию — она может быть не
      видна; ошибок нет (ожидаемое поведение).

## 5. Контекстное меню — удаление (CTM7)

- [ ] Пункт «Удалить» виден только при `EnableDelete = true`.
- [ ] Подтверждение дословно: «Вы уверены, что хотите удалить [Название ноды]?».
- [ ] «Да» → `DeleteAsync(nodeId)`; уровень родителя перезагружен; выделение снято, если удаляли
      выделенный. «Отмена» — ничего.

## 6. Кастомные операции (CTM2, CTM7)

- [ ] Пункты из `CustomMenuItems` отображаются с label и иконкой.
- [ ] Выбор пункта вызывает `OnExecute(node)` с текущим узлом.

## 7. DnD — переупорядочивание (CTM8, только NestedSet)

- [ ] `EnableDragDrop = true`. Перетаскивание в верхнюю/нижнюю четверть строки того же родителя →
      индикатор-линия сверху/снизу.
- [ ] Подтверждение дословно: «Вы уверены, что хотите изменить порядок в рамках одной группы
      [название ноды]?».
- [ ] «Да» → `ReorderAsync(id, parentId, newL)`, где `newL` = L сиблинга, после которого встаёт
      узел (для позиции 0 — L первого сиблинга).
- [ ] Уровень перезагружен; порядок соответствует нормализации триггера; фокус на перемещённом
      узле.
- [ ] Произвольный сдвиг (не только на соседнюю позицию) работает.

## 8. DnD — переподчинение (CTM8, NestedSet и ParentKey)

- [ ] Дроп в середину строки → индикатор-рамка вокруг цели.
- [ ] Подтверждение дословно: «Вы уверены, что хотите сделать [название ноды] дочерним по
      отношению к [название ноды]?».
- [ ] «Да» → `ReparentAsync(id, targetId)`; перезагружены старый и новый уровни; фокус сохранён.
- [ ] Дроп в зону before/after ребёнка другого родителя → переподчинение к этому родителю.

## 9. DnD — запреты (CTM8)

- [ ] Попытка сделать предка ребёнком своего потомка: цель подсвечена запрещающим стилем, дроп
      игнорируется.
- [ ] NestedSet — проверка по L/R в памяти (без обращения к БД).
- [ ] ParentKey — проверка через `IsDescendantAsync` (обращение к БД).
- [ ] ParentKey, попытка reorder внутри одного родителя (before/after) → зона помечена
      запрещённой, изменений нет.
- [ ] Узел нельзя бросить сам на себя.

## 10. Многопользовательность и устойчивость (CTM8)

- [ ] Два одновременных сеанса (два браузера) перетаскивают разные узлы — состояние не путается
      (поля DnD — экземплярные, не static).
- [ ] Уход со страницы во время перетаскивания/рендера не роняет circuit.

## 11. Обновление данных — общий инвариант (CTM6)

- [ ] После любой операции обновляются ТОЛЬКО затронутые уровни; раскрытость и выделение прочих
      узлов сохранены.
- [ ] Фокус остаётся на выделенной ноде, если она не была удалена.

## Отчёт

Агент возвращает список пунктов с отметками. Для каждого не пройденного пункта — краткое описание
факта и номер промта, к которому нужно вернуться. Логику не менять без согласования, если
расхождение с промтом.
