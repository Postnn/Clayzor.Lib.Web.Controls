# TF_D — панель над деревом: кнопка фильтра, бейдж, tooltip, удаление

Строим панель и подключаем `ClayFilterDialog`. На этом шаге дерево **хранит** установленное
дерево фильтра и показывает его на панели, но **ещё не исполняет** (загрузка по фильтру — TF_E).
Так панель тестируется отдельно от сложного SQL.

## Прочитать

- результат **TF_C** — `BuildFilterColumns()`;
- `Components/Filter/ClayFilterDialog.*` — параметры (`Root`, `Columns`, `LookupOptions`),
  как открывается (`IDialogService.ShowExAsync`), что возвращает (`ClayFilterGroupNode`);
- `Components/Grid/ClayGrid.Filtering.cs` — `OpenCompositeFilterDialog`, бейдж
  (`ClayFilterDescriptionBuilder.CountActiveLeaves`), текст (`BuildText`) — **образец вызова**;
- `Components/Grid/ClayGrid.razor` — как выглядит кнопка фильтра на панели грида (иконка,
  бейдж) — визуально повторить;
- `Components/Tree/ClayTreeView.razor`, `ClayTreeView.razor.cs` — куда вставить панель;
- `wwwroot/css/clay.css` — классы `clay-tree-*`, куда добавить `clay-tree-toolbar-*`.

## 1. Панель

Над деревом — контейнер `div.clay-tree-toolbar`, **шириной с дерево** (тот же контейнер/ширина,
что у `.clay-tree`; проверить, что панель и дерево в одном ограничивающем блоке). Элементы слева
направо:

1. **Кнопка настраиваемого фильтра** — `MudIconButton` с `Icons.Material.Filled.FilterAlt`
   (та же иконка, что у грида). Клик → `OpenTreeFilterDialogAsync()`.
   - если фильтр установлен → бейдж с числом условий: `MudBadge` +
     `ClayFilterDescriptionBuilder.CountActiveLeaves(_filterRoot)`, скрыт при 0;
   - **tooltip** кнопки — текстовое представление фильтра
     `ClayFilterDescriptionBuilder.BuildText(_filterRoot, getDisplayName)`; при пустом фильтре —
     обычная подсказка «Фильтр». **Чипы на панель не выводим** (в отличие от трея грида).
2. **Кнопка удаления фильтра** — `MudIconButton` `Icons.Material.Filled.Close`, видна **только**
   при установленном фильтре. Клик → `ClearTreeFilterAsync()` (обнулить `_filterRoot`,
   перезагрузить дерево в обычный режим).

Панель видна всегда, когда фильтр доступен (`BuildFilterColumns()` непуст). Если фильтруемых
колонок нет — панель можно не рисовать (или рисовать пустой — решить, отметить).

## 2. Вторая строка — счётчик (заготовка)

Вторая строка панели, **только при установленном пользовательском фильтре**: «Найдено записей:
N» / при превышении «Найдено более N записей. Отображаются только N, уточните критерии поиска.»
На этом шаге числа ещё нет (фильтр не исполняется) — вывести **заглушку-контейнер** `div`,
скрытый, с готовой разметкой; наполнение подключит TF_E. Тексты — константами (в `ClayFilterStrings`
или новом `ClayTreeStrings`, по стилю дерева).

## 3. Открытие диалога

```csharp
/// <summary>Открывает настраиваемый фильтр дерева. Применение заменяет дерево фильтра и (в TF_E) перезагружает.</summary>
private async Task OpenTreeFilterDialogAsync()
{
    var cols = BuildFilterColumns();                       // TF_C
    var parameters = new DialogParameters<ClayFilterDialog>
    {
        { x => x.Root,    _filterRoot ?? new ClayFilterGroupNode() },
        { x => x.Columns, cols },
        // LookupOptions — если у дерева есть справочники значений (по TF_A); иначе не передавать
    };
    var dialog = await DialogService.ShowExAsync<ClayFilterDialog>("Настраиваемый фильтр", parameters, options);
    var result = await dialog.Result;
    if (result is { Canceled: false, Data: ClayFilterGroupNode root })
    {
        _filterRoot = root;
        await ApplyFilterAsync();       // в TF_D — просто ReloadAsync()/StateHasChanged(); TF_E заменит на режим фильтра
    }
}
```

`_filterRoot` (`ClayFilterGroupNode?`) — новое поле дерева, единый источник истины фильтра
(по образцу грида). `ApplyFilterAsync` в этом шаге — заглушка: обновляет панель (бейдж,
tooltip, кнопку удаления) и вызывает обычную перезагрузку. Реальное исполнение — TF_E.

Диалоговые опции (`DialogOptionsEx`, размеры, drag) — скопировать у грида, чтобы диалог
выглядел одинаково.

## Ловушки

- **StyleGuard.** Цвета/рамки панели и пометок — только `--mud-palette-*` в `clay.css`,
  не inline. Структурные inline (`display:flex`, ширина) — можно.
- **Ширина панели = ширина дерева.** Если дерево в `div.clay-tree` с своей шириной/скроллом —
  панель обернуть в тот же внешний контейнер, а не шире. Проверить на широком дереве
  (горизонтальный скролл) и узком.
- **Пустой фильтр после диалога.** Пользователь нажал «Сбросить» в диалоге → вернётся пустой
  `ClayFilterGroupNode` → трактовать как «фильтра нет» (спрятать бейдж/удаление), не «фильтр
  из нуля условий».

## Не делай

- Не исполняй фильтр SQL-запросом с предками — TF_E (в этом шаге `ApplyFilterAsync` = обычная
  перезагрузка).
- Не рисуй чипы фильтра на панели (только tooltip).
- Не делай пометки «(отфильтровано)»/«(!)» — TF_F.
- Не трогай грид и общий диалог (только вызываем его).
- Не заводи параметр тега под панель — видимость/поведение из `_filterRoot` и опций.
