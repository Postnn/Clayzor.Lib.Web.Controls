## Что строим

Дереву нужен фильтр — тот же **настраиваемый фильтр** (`ClayFilterDialog`: группы И/ИЛИ,
неограниченная вложенность), что и у грида, плюс своя логика показа результатов, панель,
подсветка, значения по умолчанию, сохранение состояния и выделение узла.

**Разграничение терминов (чтобы не путать):**
- `ClayFilterDialog` — **настраиваемый** фильтр (дерево условий И/ИЛИ). **Его использует дерево.**
- `ClayFilterColumnInfo` — описание **фильтруемого поля** (SqlName, DisplayName, тип, справочник).
  Не фильтр, а вход для диалога. Дерево собирает список из колонок `SelectSql`.
- `ClayColumnFilterDialog` (одна колонка, ≤2 условия) — **гридовый**, дерево его не трогает.

## Модель поведения (согласована с заказчиком — не пересматривать)

### Три режима загрузки дерева

1. **Ленивый (обычный).** Корни; клик разворачивает один уровень запросом. Сюда же —
   **дефолтный фильтр** (см. ниже): подставляется как `WHERE` в ленивый запрос уровня,
   механизм предков и пометки **не** включает.
2. **Восстановление состояния.** Не набор раскрытых веток, а **один якорь** — путь до одной
   ноды (см. «Состояние»). Восстанавливается один путь, лениво по уровням.
3. **Фильтр (пользовательский, не дефолтный).** SQL: наложить условия → взять совпадения
   `TOP(@max+1)` → добрать **предков** (Nested — диапазоном `[L..R]`, ParentKey — рекурсивным
   CTE вверх) → каждая нода помечена в SQL флагами (сама совпала / есть совпавшие потомки).
   Набор строится целиком, в пределах `MaxFilterRecords` **совпадений** (предки не считаются).

**Ленивость внутри фильтра не умирает.** Если пользователь свернёт отфильтрованную ноду и
развернёт снова → обычный ленивый запрос уровня, показываются **все** дети, пометка
«(отфильтровано)» с этой ноды **снимается** (детей больше не скрываем).

### Правила показа при фильтре (из задания)

1. Верхний уровень (без родителей) выводится всегда.
2. Для каждой совпавшей ноды выводятся все её родители.
3. Родители, не удовлетворяющие фильтру, **не** считаются в счётчике найденных.
4. Рядом с родителем, содержащим отфильтрованных потомков → «(отфильтровано)» (в скобках, цветом).
5. Рядом с совпавшей нодой → «(!)» (в скобках, тем же цветом).
6. Нода, которая и сама совпала, и содержит совпавших потомков → **обе** надписи.
7. Если активен **только дефолтный** фильтр → надписи п.4–6 **не** выводятся.
~~8. Подсветка совпавшего фрагмента в тексте ноды~~ — **отложена** (согласовано): `TextColumn` —
   форматное поле (в общем случае SQL-выражение), поэтому «какой фрагмент подсветить» в общем
   случае неразрешимо без разбора формата. Требует отдельного решения; в TF не делается.

Пункт 6 (обе надписи) решается на уровне SQL-свёртки: нода в наборе предков и в наборе
совпадений — агрегируется в два независимых флага `_isMatch` (сама совпала) и
`_hasMatchChildren` (есть совпавшие потомки).

### Дефолтный фильтр vs пользовательский

- **Дефолтный** (значения по умолчанию из опций, п. «значения по умолчанию») — **тихое
  ограничение выборки**: WHERE в ленивом запросе, ленивость и шевроны как обычно, пометок нет,
  строки «Найдено записей» нет.
- Пользователь может **изменить** дефолтное значение → как только состав условий отличается от
  дефолтного, включается полноценный режим фильтра (предки, пометки, счётчик).
- Признак — флаг `IsDefault` на условии (как `ClayGridUrlFilterParser` различает
  forced/default). **Все** активные условия `IsDefault` → режим дефолтного фильтра.

### Состояние (в настройки по CLID)

Хранятся **два** строковых ключа (не набор раскрытых веток — большое дерево тормозит браузер):
- `LastExpandedId` — якорь последней раскрытой пользователем ноды;
- `SelectedIds` — выделение. **В TF режим одиночный** → набор из ≤1 элемента (форма набора —
  задел под множественный выбор, см. ниже).

**Восстановление пути:** ведущий ориентир — выделенная нода. Если `LastExpandedId` — предок
выделенной, путь до выделенной покрывает якорь → восстанавливаем один путь до `SelectedId`.
Если выделения нет → путь до `LastExpandedId`. Один путь, лениво по уровням.

### Выделение

- В TF — **одиночное** (`SelectionMode.Single`): клик подсвечивает ноду, `SelectedIds` = {id}.
- Сохраняется/восстанавливается вместе с состоянием.
- **Задел под множественный выбор (чекбоксы, как групповые операции грида):** режим —
  свойство `ClayTreeOptions.SelectionMode` (`None|Single|Multiple`), состояние — **набор**
  `SelectedIds` уже сейчас. Переход к `Multiple` добавит ветку рендера (чекбокс) и каскад,
  **не меняя** форму состояния и контракт. Каскад на потомков/родителей в TF **не делаем**, но
  SQL-предков/потомков проектируем переиспользуемым (Nested — диапазон `[L..R]`, тот же
  механизм, что предки при фильтре).

## Настройки — куда что (конвенция CGO/CGR1)

- **`ClayTreeOptions`** (экземпляр дерева на странице): `MaxFilterRecords`, список исключённых
  из фильтрации колонок, значения по умолчанию на колонку, сопоставление
  «query-параметр → колонка», `SelectionMode`, флаги показа пометок.
- **`ClayTreeDynamicSettings`** (уровень приложения, из конфигурации, через DI — новый класс
  по образцу `ClayGridDynamicSettings`): имя таблицы настроек, имя параметра сохранения,
  имя CLID-параметра. **Не** в options — это конфигурация, не настройка страницы.

`MaxFilterRecords` в задании назван «тегом компонента», но по правилу библиотеки конфигурация
живёт в options → `ClayTreeOptions.MaxFilterRecords` (согласовано).

## Панель над деревом (из задания)

Панель шириной с дерево, элементы слева направо:
- кнопка настраиваемого фильтра (та же, что на панели грида); если фильтр установлен — бейдж
  с числом условий (переиспользовать `ClayFilterDescriptionBuilder.CountActiveLeaves`);
- tooltip кнопки — текстовое представление фильтра (`ClayFilterDescriptionBuilder.BuildText`);
  **чипы на панель не выводить**;
- при установленном фильтре — кнопка удаления фильтра рядом;
- вторая строка при установленном фильтре: «Найдено записей: N»; если совпадений
  `> MaxFilterRecords` → «Найдено более N записей. Отображаются только N, уточните критерии
  поиска.»

## Зафиксированные решения (не пересматривать)

0. **`ParentColumn` задан всегда, в обоих режимах** (подтверждено заказчиком). CTE вверх и
   построение цепочки предков полагаются на это. Само поле в схеме сейчас опционально —
   необязательность не трогаем (правка CT1 вне рамок), но в TF полагаемся на наличие; TF_A это
   проверяет на стенде.
1. **Nested — диапазон, ParentKey — CTE.** Предки совпавших: Nested — `predok.[L] < node.[L]
   AND predok.[R] > node.[R]`; ParentKey — рекурсивный CTE вверх по `ParentId`
   (2008 R2 поддерживает `WITH ... UNION ALL`). Пример CTE — в TF_E.
2. **Пометки считаются в SQL** (CASE/агрегация), не в C#. Флаги `_isMatch`, `_hasMatchChildren`
   приходят в наборе. Причина: один проход, консистентно с «предки одним запросом».
3. **`MaxFilterRecords` ограничивает совпадения**, не итоговый набор. `TOP(@max+1)` на
   совпадениях до добора предков; пришло `> @max` → показать «найдено более N».
4. **Дефолтный фильтр = WHERE в ленивом режиме.** Не включает предков/пометки/счётчик.
5. **Состояние — два ключа** (`LastExpandedId`, `SelectedIds`), не набор веток. Восстановление —
   один путь, ведущий ориентир — выделенная нода.
6. **Выделение в TF — одиночное**, состояние — набор (задел под чекбоксы). Каскад — не в TF.
7. **`ClayColumnFilterDialog`/`ClayColumnValueFilterDialog` — гридовые, дерево не использует.**
   Дереву нужен только `ClayFilterDialog`.
8. **Всё, что делает дерево с SQL, — в `Clayzor.Lib.Entities/Tree/`.** Controls SQL не
   выполняет (правило решения; в дереве уже соблюдено).
9. **Behavior-preserving для грида.** Ни один шаг TF не трогает грид. Общий `ClayFilterDialog`
   после CF — read-only для этой серии (правим только вызовы со стороны дерева).

## Итоговый чек-лист (после TF_H)

- панель над деревом шириной с дерево; кнопка фильтра, бейдж с числом условий, tooltip с
  текстом фильтра, кнопка удаления;
- установить фильтр → дерево показывает совпадения со всеми предками; «(!)» у совпавших,
  «(отфильтровано)» у родителей скрытых потомков, обе надписи по п.6;
- «Найдено записей: N»; при превышении — «более N»;
- свернуть отфильтрованную ноду и развернуть → все дети, пометка снята, ленивый запрос;
- дефолтный фильтр → тихое ограничение, без пометок и счётчика, ленивость цела;
- изменить дефолтное значение → включается полный режим фильтра;
- выделить ноду → подсветка; уйти/вернуться → выделение и путь восстановлены (по правилу
  якоря/выделенной);
- query-параметр устанавливает фильтр (сопоставление из опций);
- фильтр сохраняется в настройки по CLID, восстанавливается при загрузке;
- Nested и ParentKey дают одинаковый видимый результат при одном фильтре;
- тёмная тема; цвет пометок и подсветки — через `--mud-palette-*`.
