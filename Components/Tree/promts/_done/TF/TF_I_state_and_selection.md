# TF_I — состояние дерева (якорь + выделение) и одиночное выделение

Сохраняем и восстанавливаем состояние дерева по CLID: **два** ключа — якорь последней раскрытой
ноды и выделение. Плюс сам механизм одиночного выделения узла (клик подсвечивает).

## Модель (из оркестратора — не пересматривать)

- Состояние = **два** строковых значения (не набор раскрытых веток — большое дерево тормозит
  восстановление):
  - `LastExpandedId` — якорь последней раскрытой пользователем ноды;
  - `SelectedIds` — выделение; **в TF режим одиночный** → набор из ≤1 элемента (форма набора —
    задел под чекбоксы).
- **Восстановление пути:** ведущий ориентир — выделенная нода. Если `LastExpandedId` — предок
  выделенной, путь до выделенной покрывает якорь → восстанавливаем **один путь до `SelectedId`**.
  Если выделения нет → путь до `LastExpandedId`. Один путь, лениво по уровням.
- Задел под множественный выбор: `SelectionMode` (TF_B), `SelectedIds` — набор; каскад не тут.

## 1. Форма состояния

Заменить прежнее «набор раскрытых» на два ключа:

```csharp
/// <summary>Сохраняемое состояние дерева: якорь раскрытия и выделение.</summary>
public sealed class ClayTreeState
{
    /// <summary>Идентификатор последней раскрытой пользователем ноды (якорь восстановления пути).</summary>
    public string? LastExpandedId { get; set; }

    /// <summary>Выделенные ноды. В текущей версии — не более одной (режим Single); набор — задел под Multiple.</summary>
    public HashSet<string> SelectedIds { get; set; } = [];
}
```

Прежнее поле `ExpandedIds` (набор веток) — **удалить**: восстановление по набору больше не
используется (причина — производительность). Проверить всех потребителей `ExpandedIds` в
`Expansion`/`Loading` и перевести на новую модель. Это меняет CT1-поведение «восстанавливать
все раскрытые ветки» на «восстанавливать один путь» — **согласовано заказчиком**, зафиксировать.

## 2. Персистентный стор по CLID

Сейчас `ClayTreeMemoryStateStore` (in-memory, circuit). Добавить **вторую реализацию**
`IClayTreeStateStore`, пишущую в ту же таблицу настроек, что грид, по CLID:

- `ClaySqlTreeStateStore(DbManager db, ClayTreeDynamicSettings settings, ...)` — сериализует
  `ClayTreeState` (якорь + выделение) в параметр `StateParamPrefix + treeId`, пишет/читает по
  CLID через инфраструктуру, найденную в TF_A п.7 (`ClayGridUserParamsData` или её аналог);
- SQL — в `Clayzor.Lib.Entities`, не в Controls (правило слоёв);
- сериализация — простая (два поля): JSON или `ключ=значение`, по стилю `GridStateSerializer`;
- регистрация: в `AddClayTree` выбирать реализацию (memory для стенда без БД / sql для
  приложения) — по образцу того, как грид переключает сторы, либо параметром. Не ломать
  стенд, где БД может не быть.

**CLID** берётся из query по `ClayTreeDynamicSettings.ClientIdQueryParam` (как грид); нет CLID →
0 (как грид).

## 3. Одиночное выделение

- новое поле `_selectedIds` (`HashSet<string>`), свойство `IClayTreeView.SelectedIds`;
- клик по тексту ноды (сейчас `OnNodeClick`) в режиме `SelectionMode.Single`: очистить набор,
  добавить `node.Id`, `StateHasChanged`, сохранить состояние; `OnNodeClick` для внешнего
  подписчика оставить (не ломать TF-страницу);
- `SelectionMode.None` → клик не выделяет (текущее поведение); `Multiple` → не в TF (ветку не
  писать, но `SelectedIds`-набор к ней готов);
- рендер: выделенная нода — класс `clay-tree-node--selected` в `clay.css`, фон через
  `--mud-palette-action-selected` (не свой цвет);
- сохранять выделение в состояние (п.2) при изменении.

## 4. Сохранение якоря и восстановление пути

- при **ручном** раскрытии ноды (клик по шеврону, `ToggleAsync` → expand) обновлять
  `LastExpandedId = node.Id` и сохранять состояние (дебаунс не обязателен, но не чаще разумного);
- при загрузке дерева (не в режиме фильтра): прочитать состояние по CLID → определить целевую
  ноду пути (выделенная, если есть; иначе якорь) → **восстановить один путь** от корня до неё:
  последовательно (ловушка MARS) раскрывать уровни вниз по цепочке предков целевой ноды;
  - цепочку предков целевой ноды получить одним запросом (Nested — диапазон, ParentKey — CTE
    вверх; **тот же билдер, что предки в TF_E** — переиспользовать, не дублировать), затем
    раскрывать по ней;
  - выделить `SelectedId`, если задан;
- если целевой ноды больше нет в данных → молча игнорировать, дерево открывается в корнях.

## Ловушки

- **Фильтр важнее состояния при загрузке.** Если активен пользовательский фильтр (URL/сохранён)
  — грузим режим фильтра (TF_E), путь состояния не восстанавливаем (набор и так раскрыт).
  Порядок: фильтр → иначе состояние. Зафиксировать.
- **Последовательность запросов.** Восстановление пути — строго последовательный обход вниз
  (MARS выключен). Не `Task.WhenAll`.
- **Задел под Multiple.** `SelectedIds` — набор уже сейчас; сериализация состояния должна
  переживать >1 элемента (на будущее), даже если Single кладёт один. Не сериализовать как
  скаляр «первый элемент».
- **Миграция старого состояния.** Если в таблице лежит состояние старой формы (набор веток из
  CT1) — при чтении не падать: неузнанный формат → пустое состояние (открыть в корнях).

## Не делай

- Не восстанавливай набор раскрытых веток (старое поведение) — только один путь.
- Не делай множественный выбор и каскад — только Single (набор готов, ветка Multiple не пишется).
- Не выполняй SQL в Controls (стор и цепочка предков — в Entities).
- Не трогай грид, общий фильтр, режим фильтра TF_E (только переиспользуй билдер предков).

## Проверка

- unit-тест сериализации `ClayTreeState` (round-trip: якорь + набор из 0/1/2 элементов);
- ручной (`/tree-test`, приложение с БД):
  - раскрыть несколько уровней, кликнуть ноду (выделить) → уйти на `/` → вернуться →
    восстановлен **путь до выделенной** ноды, она подсвечена;
  - выделить ноду в одной ветке, раскрыть глубже в другой → якорь не предок выделенной →
    восстанавливается путь до **выделенной** (ведущий ориентир);
  - без выделения: раскрыть глубокую ноду → вернуться → восстановлен путь до **якоря**;
  - большое дерево: восстановление быстрое (один путь, не все ветки);
  - активный фильтр при загрузке → грузится фильтр, не путь состояния;
  - выделение сохраняется между сессиями; `SelectionMode.None` → клик не выделяет;
  - стенд без БД (memory-стор) — не падает, состояние живёт в пределах circuit;
- цвет выделения читаем в обеих темах;
- `dotnet build` + `dotnet test` — зелёные; грид не затронут.
