# TF_F — пометки «(отфильтровано)» / «(!)» и ленивый разворот отфильтрованной ноды

Данные и флаги (`IsMatch`, `HasMatchChildren`) уже приходят из TF_E. Здесь — рисуем пометки
(правила 4–6) и обрабатываем ручной разворот отфильтрованной ноды (показать всех детей, снять
пометку). Подсветка текста (правило 8) в этой серии **не делается** — отложена (см. TF0).

## Правила показа (из задания)

- **4.** Рядом с родителем скрытых совпавших потомков → «(отфильтровано)» (в скобках, цветом);
- **5.** Рядом с совпавшей нодой → «(!)» (в скобках, тем же цветом);
- **6.** Нода и сама совпала, и содержит совпавших потомков → **обе** надписи;
- **7.** Если активен **только дефолтный** фильтр → пометок нет (обеспечит TF_G, здесь — флаг
  `_marksVisible`, по умолчанию true в режиме фильтра).

Соответствие флагам TF_E: «(!)» ↔ `IsMatch`; «(отфильтровано)» ↔ `HasMatchChildren`. Обе ↔ оба
флага. Никакой новой логики подсчёта — только рендер по готовым флагам.

## 1. Пометки в `ClayTreeNodeView`

После текста узла (`<span class="clay-tree-node-text">`), в режиме фильтра и при `_marksVisible`:

```razor
@if (Tree.MarksVisible)
{
    @if (Node.IsMatch)
    {
        <span class="clay-tree-mark clay-tree-mark--match" title="Удовлетворяет фильтру">(!)</span>
    }
    @if (Node.HasMatchChildren)
    {
        <span class="clay-tree-mark clay-tree-mark--filtered" title="Показаны не все потомки">(отфильтровано)</span>
    }
}
```

Порядок при обеих (правило 6): «(!)» затем «(отфильтровано)» — согласовать и зафиксировать.
`Tree.MarksVisible` — свойство компонента: true в пользовательском режиме фильтра, false в
обычном и в дефолтном (TF_G выставит false для только-дефолтного).

Цвет — **только** через `--mud-palette-*` (StyleGuard). Класс `clay-tree-mark` в `clay.css`:
`.clay-tree-mark--match` и `.clay-tree-mark--filtered` — цветом (например
`--mud-palette-warning`/`--mud-palette-info`, подобрать читаемо в обеих темах), мелким шрифтом,
`margin-left`. Тексты «(!)»/«(отфильтровано)» — константами в `ClayTreeStrings`, не хардкод в
разметке.

## 2. Ленивый разворот отфильтрованной ноды (ключевое)

Из оркестратора: свернуть отфильтрованную ноду и развернуть снова → **обычный ленивый запрос
уровня**, показываются **все** дети, пометка «(отфильтровано)» с этой ноды **снимается**.

В `ToggleAsync`/`ExpandNodeAsync` (после CTF): при разворачивании узла, у которого дети пришли
из фильтр-набора, поведение зависит от того, полный ли это набор детей:

- у ноды из фильтр-набора `IsLoaded = true`, но `Children` — только совпавшая ветвь, не все дети;
- поэтому вводим признак `ChildrenAreFiltered` (bool на `ClayTreeNode`): true у нод, чьи дети
  пришли из фильтр-набора (не полный уровень);
- при **ручном** разворачивании такой ноды (клик по шеврону): если `ChildrenAreFiltered` →
  сбросить `IsLoaded=false`, очистить `Children`, выполнить обычный `EnsureChildrenLoadedAsync`
  (полный уровень, без фильтра), затем `ChildrenAreFiltered=false` и `HasMatchChildren=false`
  (пометка снята — показаны все дети);
- сворачивание такой ноды детей из памяти не выбрасывает (как обычно), но при следующем ручном
  разворачивании срабатывает правило выше **один раз** (после первой полной догрузки нода
  ведёт себя обычно).

**Тонкость:** отличать «ручной разворот» (клик пользователя) от «показ набора при установке
фильтра» (там ноды сразу `IsExpanded=true`, но это не клик). Правило перезагрузки применяется
только к клику по шеврону, не к построению набора. Убедиться, что построение набора (TF_E) не
дёргает эту ветку.

## Ловушки

- **`ChildrenAreFiltered` сбрасывается по всей ветке?** Нет — только у разворачиваемой ноды.
  Её потомки в наборе остаются отфильтрованными, пока пользователь не развернёт каждого. Это
  ожидаемо: пользователь «раскрывает полностью» ноду за нодой.
- **Пометка «(!)» при ручном развороте не снимается** — она про саму ноду (совпала/нет), а не
  про детей. Снимается только «(отфильтровано)».
- **Смешанный набор.** Нода могла прийти и как совпадение (`IsMatch`), и как предок
  (`HasMatchChildren`). После полного разворота `HasMatchChildren` снимаем, `IsMatch` оставляем.

## Не делай

- Не делай подсветку текста (правило 8) — отложена.
- Не пересчитывай флаги в C# — они из TF_E; здесь только рендер и ленивый сброс.
- Не трогай счётчик «Найдено записей» (TF_E) и дефолтный режим (TF_G).
- Не выбрасывай `--mud` палитру ради «поярче» — StyleGuard и тёмная тема.

## Проверка

Ручной прогон (`/tree-test`, оба режима, фильтр «Название содержит Ноутбук»):
- у обоих ноутбуков — «(!)»; у «Ноутбуки», «Компьютерная техника», «Оборудование» —
  «(отфильтровано)»; корень ПО без пометок (нет совпадений в ветке);
- если сделать ноду, которая и совпала, и имеет совпавших потомков (фильтр по «Название
  содержит о» — «Оборудование» совпадёт само и содержит совпавших) → **обе** пометки, в
  заданном порядке;
- клик по шеврону «Компьютерная техника» (свернуть/развернуть) → показаны **все** дети
  (Ноутбуки, Мониторы — включая не совпавшие), «(отфильтровано)» с неё снято; один ленивый
  запрос уровня в профайлере;
- «(!)» на совпавших нодах после этого осталось;
- цвет пометок читаем в светлой и тёмной теме;
- снять фильтр → пометок нет;
- грид не затронут.
