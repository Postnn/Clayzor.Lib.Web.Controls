## 2. Тесты, которые стоит добавить именно здесь (сквозные, на чистой логике)

- **Одинаковый результат режимов.** Для одного и того же фильтра билдеры Nested и ParentKey
  дают разный SQL, но семантически один набор. Тест на SQL этого не докажет — поэтому проверить
  инвариант иначе: на **сборке дерева из плоского набора** (функция из TF_E, если она чистая):
  один и тот же плоский набор с флагами → одинаковая структура дерева, `Level` считается от
  родителя, `HasMatchChildren` не теряется. Если функция не выделена в чистую — отметить как
  замечание, не рефакторить в этом шаге.
- **Счётчик совпадений.** Из набора с флагами: число `IsMatch == true` = ожидаемое; предки не
  считаются (правило 3). Если подсчёт делается в C# — покрыть; если в SQL — проверить, что
  `_filterCapped` выставляется при `> max` (тест на логику определения, не на SQL).
- **Приоритет источников фильтра** (TF_G, ловушка): forced URL > сохранённое > default URL >
  `FilterDefaults`. Тест на функцию разрешения приоритета, если она выделена.
