# CTP — кейсет-пагинация уровня `ClayTreeView` (оркестратор)

> Серия развития `ClayTreeView`. Правила исполнения — `/AGENTS.md`
> (**Think → Simplicity → Surgical → Goal-Driven**). Пользовательский текст — на русском.
> Каждый новый public/protected член — с `/// <summary>`. Git — только по указанию.
> `AGENTS.md`/`docs/` правит только шаг **CTP3**.
>
> **Один файл = один заход = один коммит.** Класть в `Components/Tree/promts/`.
> Выполняется **до** серий CF/TF (фильтр): пагинация живёт в ленивом уровне, фильтр опирается
> на неё, не наоборот.

---

## Задача

При раскрытии узла с тысячами прямых детей загружать и показывать уровень **порциями**, а не
целиком: первая порция сразу, следующие — по требованию («загрузить ещё» кнопкой или
автоподгрузкой при доскролле). Не убивать браузер числом DOM-элементов и сервер объёмом
выборки.

Масштаб (со слов заказчика): широкий уровень, **тысячи** прямых детей у одной ноды.

---

## Модель решения (согласовано с заказчиком — не пересматривать)

1. **Только режим `NestedSet`.** Пагинация опирается на левый ключ `L`. В `ParentKey` колонки
   `L` нет и стабильно-уникального ключа сортировки уровня тоже — там уровень грузится
   **целиком**, как сейчас. `LevelPageSize`, заданный при `ParentKey`, молча игнорируется
   (не ошибка; отметить в докстринге опции).
2. **Кейсет (seek), а не `OFFSET/FETCH` и не `ROW_NUMBER`.** `OFFSET/FETCH` запрещён (SQL Server
   2008 R2); `ROW_NUMBER` деградирует на дальних страницах. Кейсет прыгает по индексу и не
   дорожает с номером страницы.
3. **Курсор — одно значение `L`** последней ноды загруженной порции. Сортировка уровня всегда
   по `L`, `L` уникален по построению nested set → составной курсор `(поле, Id)` не нужен.
   Следующая порция: `<диапазон прямых детей родителя> AND s.[L] > @lastL ORDER BY s.[L]`.
4. **`TOP (@n + 1)`** — берём на одну строку больше размера порции; пришло `n+1` → «есть ещё»
   (последнюю лишнюю в UI не показываем, но её `L` не используем как курсор). Пришло `≤ n` →
   уровень дочитан.
5. **Догрузка ДОПИСЫВАЕТ в `Children`**, не заменяет. У ноды появляются `LoadedAllChildren`
   (дочитан ли уровень) и `LastChildCursor` (значение `L` последнего загруженного ребёнка).
6. **Два режима триггера**, настраивается в экземпляре (`ClayTreeOptions.LevelPagingMode`):
   `Button` (кнопка «Загрузить ещё N» в конце уровня) и `Scroll` (сентинел + `IntersectionObserver`
   через JS-интероп). SQL и загрузка **общие**; разветвление — только в разметке.
7. **Размер порции — `ClayTreeOptions.LevelPageSize`.** `0` (или дефолт) → пагинация выключена,
   поведение как сейчас (уровень целиком).
8. **Совместимость с будущей алфавитной сортировкой.** Заказчик планирует сортировку детей по
   тексту с **физической перестройкой `L`**. Пока порядок отображения совпадает с порядком `L`,
   курсор = `L` корректен всегда. Смена этого принципа (логическая сортировка без перестройки
   `L`) потребует пересмотра курсора — зафиксировать как условие в докстринге билдера.
9. **Не пересекается с фильтром (серия TF).** Пагинация — свойство **ленивого** уровня
   (`EnsureChildrenLoadedAsync`). Фильтр-режим строит набор целиком в пределах `MaxFilterRecords`
   и пагинацию уровня не использует. Стык один: ленивый разворот отфильтрованной ноды (TF_F)
   вызовет уже-пагинированный ленивый путь — это подхватится само, отдельного кода не требует.
   Ссылку на это добавит серия TF, здесь — только «след» в CTP3.

## Зафиксированные решения (сводка запретов)

- Только NestedSet; ParentKey не пагинируется.
- Кейсет по `L`; не `OFFSET/FETCH`, не `ROW_NUMBER`, не CTE.
- Курсор — одно `L`; составной курсор не вводить (не нужен по построению).
- Догрузка дописывает в `Children`; полную перезагрузку уровня не делать (кроме `ReloadAsync`).
- SQL/загрузка общие для обоих режимов триггера; разветвление только в разметке.
- Пагинация — в ленивом уровне; фильтр про неё не знает.
- `DbManager` в Controls не создавать; SQL — только в `Clayzor.Lib.Entities`.
- StyleGuard: визуальные inline-стили запрещены, цвета — `--mud-palette-*`.

## Итоговый чек-лист (после CTP3, NestedSet, `LevelPageSize = N`, узел с >N детей)

- при раскрытии показаны первые N детей + признак «есть ещё» (кнопка или автоподгрузка);
- режим `Button` → кнопка «Загрузить ещё N» в конце уровня дописывает следующую порцию;
- режим `Scroll` → доскролл до конца уровня подгружает следующую порцию сам;
- на каждую порцию — **один** SQL-запрос с кейсетом `[L] > @lastL`, без роста стоимости на
  дальних порциях (профайлер: план не меняется от номера порции);
- когда уровень дочитан — кнопка/сентинел исчезают, `LoadedAllChildren = true`;
- свернуть/развернуть узел → уже загруженные порции на месте, лишних запросов нет;
- порядок детей стабилен между порциями (по `L`), дублей и пропусков на границах нет;
- `LevelPageSize = 0` → пагинация выключена;
- тёмная тема; в консоли браузера нет ошибок JS (режим Scroll).

## Вне рамок серии

Полная виртуализация видимой области (CT8) — отдельный шаг, если появятся десятки тысяч
**одновременно видимых** нод. Пагинация уровня решает широкий уровень; глубокое дерево целиком
(много раскрытых веток суммарно) — не её задача. Алфавитная сортировка с перестройкой `L` —
отдельная серия; здесь только зафиксировано, что курсор `L` её переживает.
