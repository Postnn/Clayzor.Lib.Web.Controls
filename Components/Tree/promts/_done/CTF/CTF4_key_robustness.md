# CTF4 — устойчивость строковых ключей узлов (null и единый источник)

> Заплатка к CT1. Читать `CTF0_README_fixes.md`. Низкий приоритет — на демо-данных не
> проявляется, но чинит две мины на будущее. Правила — `AGENTS.md`.

## Две проблемы

### 1. `ToKey(null)` → `""` — коллизия ключей

`ClaySqlTreeDataSource.ToKey`:

```csharp
public static string ToKey(object? value) => value?.ToString() ?? "";
```

Если идентификатор узла придёт `null` или `DBNull.Value`, ключ станет `""` (для `DBNull` —
строкой `"System.DBNull"`, что ещё хуже). Два узла с таким `Id` затрут друг друга в `_byId`,
и раскрытие одного будет управлять другим. Для первичного ключа таблицы это маловероятно, но
`ClayTreeData.MapRow` уже страхуется от `null` в `_haschildren`
(`Convert.ToInt32(... ?? 0)`), то есть `null`/`DBNull` в потоке значений — реальность, а не
паранойя.

### 2. Ключ узла вычисляется в двух местах — хрупко

- `_byId` индексируется по `node.Id` (`ClayTreeView.Loading.IndexNodes`);
- `ToggleAsync` ищет узел по `ClaySqlTreeDataSource.ToKey(node.RawId)`.

Сейчас они совпадают, потому что `MapRow` задаёт `Id = ToKey(row.Id)` и `RawId = row.Id`. Но
это совпадение держится на том, что формула `Id` и `ToKey(RawId)` дают одно и то же. Если
кто-то в CT2+ изменит вычисление `Id` (префикс, нормализация), `ToggleAsync` тихо перестанет
находить узлы — клик по шеврону просто ничего не будет делать, без ошибки. Классическая мина.

## Решение

**Проблема 1 — нормализовать `DBNull` и запретить пустой ключ там, где он означает потерю
данных.** `ToKey` привести к виду:

```csharp
/// <summary>
/// Преобразует идентификатор узла в строковый ключ состояния.
/// DBNull трактуется как отсутствие значения. Пустой ключ — признак того, что источник
/// вернул узел без идентификатора; такой узел не может участвовать в состоянии.
/// </summary>
public static string ToKey(object? value)
{
    if (value is null || value is DBNull) return "";
    return value.ToString() ?? "";
}
```

И в `MapRow` (`ClaySqlTreeDataSource`) — если ключ пуст, это ошибка данных, а не штатный
случай: узел без идентификатора в дереве бессмыслен (его нельзя раскрыть, сохранить в
состоянии, найти). Не заводя новых требований, достаточно **пропускать** такие строки на этапе
маппинга уровня, чтобы битая строка не ломала `_byId`. Но пропуск меняет поведение (узел
исчезает молча) — поэтому это **вопрос к заказчику, а не самовольное решение**: см. ниже.

**Проблема 2 — единый источник ключа.** Ключ узла должен вычисляться **один раз**, при
создании узла, и переиспользоваться везде. `ToggleAsync` обязан брать ключ из `node.Id`, а не
пересчитывать из `node.RawId`.

Файл `ClayTreeView.Loading.cs`, `ToggleAsync`. Было:

```csharp
public async Task ToggleAsync(ClayTreeNode node)
{
    var key = ClaySqlTreeDataSource.ToKey(node.RawId);
    if (node.IsExpanded)
        await CollapseNodeAsync(key);
    else
        await ExpandNodeAsync(key);
}
```

Стало:

```csharp
public async Task ToggleAsync(ClayTreeNode node)
{
    // Ключ берём из узла, а не пересчитываем: node.Id — единственный источник ключа состояния.
    if (node.IsExpanded)
        await CollapseNodeAsync(node.Id);
    else
        await ExpandNodeAsync(node.Id);
}
```

`node.Id` уже равен `ToKey(row.Id)` из `MapRow` — результат тот же, но теперь ключ не
раздваивается на два независимых вычисления.

## Вопрос заказчику (не решать самому)

Что делать со строкой, у которой идентификатор пуст/`null` после `ToKey`? Варианты:
- **пропускать** узел при маппинге (не показывать) — данные не бьются, но узел молча исчезает;
- **бросать** исключение — «источник дерева вернул узел без идентификатора», строгая диагностика;
- ничего не делать (текущее поведение) — узлы схлопываются в `_byId`.

Для дерева по первичному ключу это не возникнет, поэтому **в этой заплатке менять поведение
маппинга не нужно** — только нормализация `DBNull` в `ToKey` и единый источник ключа
в `ToggleAsync`. Пропуск/исключение — отдельное решение, вынести в отчёт вопросом.

## Не делай

- Не добавляй пропуск/исключение для пустого ключа в `MapRow` без ответа заказчика.
- Не меняй тип `Id` с `string` на другой (решение CT1 — строка).
- Не трогай `ClayTreeData` и билдер — это про UI-ключи.
