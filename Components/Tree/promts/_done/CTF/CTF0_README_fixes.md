## Контекст: изменённое проектное решение

CT1 (решение 9) требовал: в `NestedSet` колонка уровня **обязательна**. Заказчик это отменил:
**`LevelColumn` в структуре таблиц не будет, колонка не используется вообще.** Реализация уже
подстроена (`Validate` Level не требует, билдер имеет ветки «без Level»), но эти ветки во
вложенных множествах некорректны — из-за чего дерево в `NestedSet` не работает глубже первого
уровня. Все заплатки чинят путь «NestedSet без Level», а не возвращают обязательность Level.

CTF1 и CTF2 — один корень (отсутствие Level), но чинятся в разных местах (SQL-предикат и
вычисление уровня в маппере), поэтому разнесены — можно ревьюить и откатывать по отдельности.
Оба нужны для корректного вида NestedSet.

CTF5 — индикатор загрузки узла. `IsLoading` не выставлялся в `EnsureChildrenLoadedAsync`,
поэтому per-node спиннер (на месте шеврона) никогда не показывался; работал только глобальный
оверлей `.clay-busy`. Добавлена установка `IsLoading` в `Loading.cs` и трёхветочный рендер
в `ClayTreeNodeView.razor` (спиннер / шеврон / распорка — взаимоисключающие). Глобальный
оверлей сделан опциональным: `ClayTreeOptions.ShowBusyOverlay` (по умолчанию `true`).
На тестовой странице `/tree-test` оверлей выключен.

CTF6 — направляющие линии иерархии (guide lines): вертикали по уровням вложенности, горизонтальный
«ус» к строке узла, обрыв у последнего ребёнка группы. Включается опцией `ClayTreeOptions.ShowLines`
(по умолчанию `false` — без регрессии). Реализовано через двухрежимный рендер в
`ClayTreeNodeView.razor` (плоский `padding-left` / вложенные `clay-tree-children--lines`)
и CSS-псевдоэлементы (`::before` для вертикали/уса, `::after` для маски обрыва). Цвет линий —
`var(--mud-palette-gray-400, #ccc)`. Попутно добавлена опция `ConnectionStringName` для
подключения дерева к другой БД через имя строки в `web.config`.

## Снятый дефект

Ранее в разбор попал «`ParentId` не заполняется». **Снят:** по полному коду
`ClayTreeData.MapRow` содержит `if (row.TryGetValue(AliasParent, out var p)) r.ParentId = p;`,
а `ClaySqlTreeDataSource.MapRow` — `ParentId = row.ParentId`. Заполнение есть; в поиске по
проекту фрагмент был обрезан, отсюда ложная тревога.

## Факты по коду (проверено в исходниках)

- Слой данных: `Clayzor.Lib.Entities/Tree/` — `ClayTreeSqlBuilder`, `ClayTreeData`,
  `ClayTreeSchema`, `ClayTreeSource`, `ClayTreeRow`, `ClayTreeHierarchyMode`. **SQL — только тут.**
- Controls: `Components/Tree/` — компонент (`ClayTreeView.*`), рендер узла (`ClayTreeNodeView`),
  источник `ClaySqlTreeDataSource`, состояние (`ClayTreeMemoryStateStore`), модели, интерфейсы.
  `DbManager` приходит в конструктор `ClaySqlTreeDataSource`; при заданном
  `ConnectionStringName` дерево создаёт свой экземпляр через `ResolveDb()`.
- `Validate()` в `NestedSet` требует `LeftColumn` и `RightColumn`, `LevelColumn` — нет. Это
  соответствует решению заказчика, не трогать.
- `ClayTreeData.BuildParams` для NestedSet кладёт `@left`/`@right` всегда, `@level` — только
  `if (LevelColumn is not null)`. Согласовано с билдером; для CTF1 новых параметров не нужно.
- `MapRow` в обоих слоях аккуратно достаёт `Left`/`Right`/`Level` с учётом `int`/`long`.
- Тесты: `tests/Clayzor.Lib.Web.Controls.Tests/ClayTreeSqlBuilderTests.cs`,
  `ClayTreeOptionsTests.cs`.
- Стенд: `scripts/tree/schema.sql` (`dbo.ClayTreeDemo`, колонка `Уровень` в таблице **есть**,
  но схема дерева её не задаёт — стенд обязан работать без неё), страница `/tree-test`.

- раскрыть «Оборудование» → **ровно** «Компьютерная техника», «Мебель», «Прочее», без внуков,
  с отступом на один уровень;

- раскрыть «Ноутбуки» → «Ноутбук Dell Latitude», «Ноутбук HP ProBook», шеврона у них нет;

- уйти на `/` и вернуться → раскрытие восстановлено;
- негативный: `SelectSql` на несуществующую таблицу → сообщение об ошибке, приложение живо;
- тёмная тема → читаемо, hover виден;
- `/medical-tests` и `/?id=140` работают как раньше.
