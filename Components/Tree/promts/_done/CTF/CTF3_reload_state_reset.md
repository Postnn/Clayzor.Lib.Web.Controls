# CTF3 — `ReloadAsync` рассинхронивает раскрытое состояние

> Заплатка к CT1. Читать `CTF0_README_fixes.md`. Средний приоритет. Правила — `AGENTS.md`.
>
> Прежний номер CTF3 (маппинг `ParentId`) **снят**: проверка по фактическому коду показала, что
> `ClayTreeData.MapRow` и `ClaySqlTreeDataSource.MapRow` `ParentId` заполняют. Этот CTF3 —
> про сброс состояния при перезагрузке.

## Симптом

Кнопка «Обновить» (`ReloadAsync`) перестраивает дерево, но набор раскрытых ключей `_expanded`
и фактически раскрытые узлы расходятся: счётчик «Раскрыто узлов: N» может показывать старое
число, а на экране — свёрнутое дерево (или наоборот). Контракт `IClayTreeView.ReloadAsync`
обещает «полную перезагрузку **с сохранением раскрытого состояния**».

## Корневая причина (проверено по коду)

`ClayTreeView.Loading.LoadRootsAsync` очищает `_roots` и `_byId`, но **не** очищает `_expanded`:

```csharp
public async Task LoadRootsAsync()
{
    _initialLoading = true;
    _error = null;
    _roots.Clear();
    _byId.Clear();
    // _expanded НЕ очищается
    ...
    _roots.AddRange(result.Nodes);
    IndexNodes(result.Nodes, null);
    await RestoreStateAsync();
}
```

Дальше `RestoreStateAsync` **добавляет** ключи в `_expanded` (`_expanded.Add(id)`), не
пересоздавая набор. При повторном `LoadRootsAsync` (кнопка «Обновить») в `_expanded` остаются
ключи от прошлого построения; новые узлы — это **другие экземпляры** `ClayTreeNode` с теми же
строковыми ключами, но их флаги `IsExpanded` сброшены (объекты новые). `RestoreStateAsync`
читает состояние из `StateStore` (там ключи есть) и восстанавливает корректно — но остаточные
ключи в `_expanded`, не совпавшие с новыми `_byId`, копятся, а `ExpandedIds` (для счётчика на
странице) отдаёт распухший набор.

Итог: источник истины раздваивается — `StateStore` и `_expanded` живут своей жизнью.

## Решение

`_expanded` — это **проекция** текущего построенного дерева, а не независимое хранилище.
Персистентное состояние живёт в `StateStore`. Значит при каждой перезагрузке `_expanded`
надо обнулять вместе с `_roots`/`_byId`, а наполняется он заново в `RestoreStateAsync`.

Файл `src/Clayzor.Lib.Web.Controls/Components/Tree/ClayTreeView.Loading.cs`, метод
`LoadRootsAsync`. Было:

```csharp
_roots.Clear();
_byId.Clear();
```

Стало:

```csharp
_roots.Clear();
_byId.Clear();
_expanded.Clear();   // проекция текущего дерева; наполнится заново в RestoreStateAsync
```

`StateStore` при этом **не трогаем** — сохранённые ключи там остаются и именно из них
`RestoreStateAsync` восстановит раскрытие. Порядок сохраняется: `LoadRootsAsync` в конце
успешной ветки уже зовёт `RestoreStateAsync`.

Проверить заодно (не менять, если верно): `RestoreStateAsync` при пустом сохранённом состоянии
и `InitialExpandLevel == 0` оставляет `_expanded` пустым — после сброса это корректно.

## Ловушка — не сохранить пустое состояние поверх реального

`RestoreStateAsync` при обнаружении отсутствующих ключей вызывает `SaveStateAsync()`. После
`_expanded.Clear()` это по-прежнему безопасно: `SaveStateAsync` пишет `[.._expanded]` **после**
того как `RestoreStateAsync` наполнил `_expanded` восстановленными ключами, а не в момент
очистки. Убедиться, что порядок в `RestoreStateAsync` не изменён: сначала наполнение, потом
`SaveStateAsync`. Если решишь тронуть `RestoreStateAsync` — не сохраняй состояние до того, как
`_expanded` восстановлен, иначе «Обновить» затрёт раскрытие пустотой.

## Не делай

- Не очищай `StateStore` в `LoadRootsAsync` — это уничтожит сохранённое раскрытие, и «Обновить»
  всегда будет схлопывать дерево.
- Не переписывай `RestoreStateAsync` под задачу — правка на одну строку в `LoadRootsAsync`.
- Не вводи второй источник истины (поле «последнее состояние») — `StateStore` уже он.

## Проверка

Ручной прогон (`/tree-test`, любой режим):

1. раскрыть три ветки на разных уровнях → счётчик «Раскрыто узлов» = 3 (или сколько раскрыто
   фактически);
2. «Обновить» → те же три ветки раскрыты, счётчик тот же, дерево не схлопнулось и не задвоило
   отступы;
3. свернуть одну ветку, «Обновить» → раскрыты две, счётчик = 2;
4. уйти на `/` и вернуться на `/tree-test` → раскрытие восстановлено (проверка, что `StateStore`
   не пострадал);
5. многократное «Обновить» подряд → счётчик стабилен, не растёт.

`dotnet build` + `dotnet test` — зелёные.
