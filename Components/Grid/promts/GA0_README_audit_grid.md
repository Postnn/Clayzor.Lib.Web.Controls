# GA0 — Аудит ClayGrid: находки и порядок исправлений

Серия GA (Grid Audit). Промты выполняются строго по порядку: GA1 → GA6.
Один шаг = один файл; файлы внутри промта пронумерованы в порядке правки.

Правила те же, что в аудите ClayTree: инъекции в SQL, потеря/некорректность параметров,
стабильность ключей, гонки, честность лимитов, аккуратность жизненного цикла.

## Сводка находок

| # | Серьёзность | Находка | Промт |
|---|---|---|---|
| 1 | **Критично (безопасность)** | `ClayDataQuery.BuildOrderBy` подставляет `SortColumn.Column` в ORDER BY **без белого списка**. В обычном режиме туда попадает `SortName` из определения (доверенно), но через **shared-ссылку** значение приходит из чужого набора: `ApplySharedParams → ApplySavedSort` кладёт в `_sortState` произвольные строки, а `ClaySharedParamValidator` проверяет только **имена** параметров, не содержимое → инъекция в ORDER BY по чужой ссылке | GA1 |
| 2 | **Критично (безопасность)** | То же для группировки в shared-режиме: `ApplySavedGroups` фильтрует по `_columnBySqlName`, но `ApplySharedParams` вызывает его до того, как гарантирован полный набор колонок — и, главное, `BuildGroupAggregateSql`/`BuildDetailOrder` подставляют `groupExprs` текстом. Нужен единый чек-пойнт валидации группировки и сортировки против `_columnBySqlName` для любого источника (saved / shared / URL) | GA1 |
| 3 | **Высокая (потеря данных состояния)** | `ClayGrid.Dynamic.Grouping.cs`: префикс параметров детального запроса группы `gk_{fullKey.GetHashCode()}_`. `string.GetHashCode()` в .NET рандомизирован — но проблема здесь не персистентность, а **коллизии в пределах одной страницы**: две разные группы с совпавшим 31-битным хешем дадут одинаковые имена параметров `@gk…0`, и Dapper бросит «parameter already added» либо выберет неверные ID. Заменить на детерминированный уникальный индекс группы | GA2 |
| 4 | **Высокая** | `DeserializeColumns`/`DeserializeSort`/`DeserializeGroups` не защищены от инъекции через сам разделитель: SqlName колонки, содержащий `,` или `:`, ломает round-trip (частый случай — вычисляемые колонки с запятой в выражении). Плюс `DeserializeColumns` молча теряет колонки с `:` в имени | GA3 |
| 5 | **Высокая** | `ApplySharedParams` вызывает `ApplySavedSort`/`ApplySavedGroups`/фильтр, но **не сбрасывает** предыдущее состояние (сортировку/группы/фильтр), накопленное из `RestoreDynamicState` этой же сессии → чужие настройки накладываются поверх личных вместо замены; также `_ = RefreshQuickSearchEffective(opt)` — проглоченный `async` без await (гонка + необработанные исключения) | GA4 |
| 6 | **Средняя** | `LoadDynamicData`: `TotalCount` и страница данных берутся **двумя отдельными запросами** без транзакции/снапшота — на активной таблице пагинация показывает «страница 5 из 4»; при `PageNumber`, вышедшем за диапазон после смены фильтра, возвращается пустая страница вместо клампа к последней | GA5 |
| 7 | **Средняя** | `BuildSearchLikeExpr`: для типа `Decimal` нет ветки CAST (число ищется как есть — на `nvarchar`-колонке ок, но `decimal` в поиске по подстроке молча не сматчится); `CONVERT(..., 104)` жёстко зашивает формат `dd.mm.yyyy`, игнорируя `col.Format` и `DateTimeLocal`/`TimeLocal` с временем → поиск по дате-времени не находит | GA5 |
| 8 | **Средняя** | `ResolveDynamicGridId`/`ResolveClientId`/`ResolveSharedId` трижды парсят `Nav.Uri` через `new Uri(...)` + `ParseQueryString`; при не-ASCII или закодированных символах в query поведение расходится с `ApplyUrlParams` (тот перебирает `qs.Keys`). Вынести единый разбор query-строки | GA6 |
| 9 | **Средняя** | `SaveParamIfChanged` обновляет кеш `_dynamicSavedParams` только после успешной записи, но `SaveDynamicState` вызывается из `LoadDynamicData` в `finally`-стиле на каждую загрузку — при частых операциях это N последовательных `INSERT`-ов в БД на каждый чих (нет батча, нет дебаунса) | GA5 |
| 10 | **Низкая** | Множество `try { … } catch { /* глушим */ }` (загрузка справочников типов 5/9, `CreateSharedLinkAsync`) глотают все исключения включая `OperationCanceledException`; ошибки справочников не логируются даже в debug | GA6 |
| 11 | **Низкая** | `#pragma warning disable CS0618` вокруг `BuildColumnFilterClause` и живой `[Obsolete]`-код `ColumnFilters` — мёртвый путь, помеченный «упраздняется в задаче 10», но не удалённый; риск случайного использования | GA6 |
| 12 | **Критично (XSS)** | `ClayHtmlSanitizer` — blacklist из трёх регулярок, тривиально обходится (`<img onerror=...>` без кавычек, `<svg/onload>`, вложенные теги). HTML-колонка рендерится через `AddMarkupContent` из данных БД → XSS в браузере. Тем же методом «санируется» `href` Link-колонки (`javascript:`/`data:` обходятся) | GA7 |
| 13 | **Высокая (Excel formula injection)** | `ClayGridExcelGenerator.SetCellValue`: строковое значение с ведущим `= + - @` присваивается `cell.Value` → ClosedXML трактует как формулу. Значения из данных грида → у получателя выгрузки выполняется `=HYPERLINK/DDE/…`. Тот же путь в динамическом экспорте | GA8 |
| 14 | **Высокая (concurrency)** | `ClayDragState.DraggedColumn` — `static` поле. В Blazor Server статика общая на весь процесс, а не на circuit. Параллельное перетаскивание колонок разными пользователями перетирает состояние → группировка/фильтр по чужой колонке | GA9 |

## Порядок выполнения

1. **GA1** — валидация ORDER BY / GROUP BY против белого списка (безопасность).
2. **GA2** — уникальные имена параметров групповых подзапросов.
3. **GA3** — надёжная сериализация состояния (экранирование разделителей).
4. **GA4** — сброс состояния при применении shared, устранение проглоченного async.
5. **GA5** — согласованность пагинации, поиск по типам, батч сохранения.
6. **GA6** — единый разбор query, обработка отмены, удаление мёртвого кода.
7. **GA7** — XSS: whitelist URL-схем, HTML-колонка как текст (безопасность).
8. **GA8** — Excel formula injection: безопасная запись строковых ячеек (безопасность).
9. **GA9** — drag-state в поле экземпляра вместо статики (concurrency).

Приоритет по риску: если чинить не по порядку, а по критичности — сначала GA7 и GA1
(активные векторы атаки), затем GA8, GA9, GA2, GA4, потом остальное.

После каждого промта: `dotnet build` чистый; прогон существующих тестов грида
(в `promts/_done/.../TG*`, `SH9_tests`, `GN*` — там же снапшоты SQL).
